# AGENTS.md

## What this repo is

A docs-only ["awesome list" of free Hungarian NLP resources](https://github.com/oroszgy/awesome-hungarian-nlp).
Exactly three tracked files, no code, no build, no package manager, no test suite:

- `README.md` — the list itself and the only file with real content.
- `SUMMARY.md` — a GitBook sidebar stub with a single entry pointing at `README.md`. Only touch it if a new top-level document is added.
- `.github/workflows/links.yml` — the lychee link checker.

"Verification" for a change here means: links resolve, and the README table of contents still matches the headings.

## Editing the list

- Entry format is one line per resource: `- [Name](url) 👌🚀💯 Short description.`
  The trailing prose is optional; some entries link several related URLs inline instead.
- The 👌 (easy to install) / 🚀 (commercial-friendly license) / 💯 (pretrained models available) notation is defined by the "Notations:" legend **under `## Tools` only**. Do not add these badges to entries in `## Language models`, `## Datasets`, `## Academy`, or `## Learning resources` — they carry no badges today.
- Entries must be *free* resources (stated in the README tagline); the Awesome badge points at the sindresorhus/awesome guidelines.
- Sub-items are nested with 3-space indent under a parent entry (e.g. the `HuLU` block) or 2-space indent (e.g. the OpenStreetMap line). Preserve the existing style rather than reformatting.
- Section order is curated, not alphabetical. Add new resources to the section they belong to; do not sort or reorder existing lines.


## Table of contents — update it by hand

The TOC in `README.md` lives between these markers and is generated by a VS Code "Markdown TOC" style extension:

```
<!-- MarkdownTOC autolink="true" markdown_preview="github" style="ordered" indent="   " -->
...
<!-- /MarkdownTOC -->
```

Rules when a heading is added, renamed, or removed:

- Ordered list, 3 spaces of indent per nesting level (`0` for `##`, `3` for `###`, `6` for `####`).
- Anchors are GitHub slugs: lowercase, spaces become `-`, punctuation dropped, so `PoS / Morphological taggers` → `#pos--morphological-taggers`.
- Duplicate headings get a numeric suffix: the two `Other` sections are `#other` and `#other-1`. A third would be `#other-2`.
- Nothing checks this for you. CI does not validate TOC anchors — see below.

## Link checking

`.github/workflows/links.yml` runs on **every push and every PR**:

- `lycheeverse/lychee-action@v1.5.1` (lychee 0.10.1), default args `--verbose --no-progress './**/*.md' './**/*.html'`.
- The action's `fail` input defaults to `false`, so **a broken link does not turn the job red**. The only signal is an auto-opened issue titled "Link Checker Report" with labels `report` and `automated issue`, created by `peter-evans/create-issue-from-file@v4` from `lychee/out.md`.
- Consequence: check the repo's open issues for "Link Checker Report" before assuming CI passed, and do not expect a red build to catch a bad URL.
- lychee only walks `*.md`/`*.html` and does **not** verify URL fragments/anchors by default, so a broken `#anchor` (including a stale TOC entry) is invisible to CI.
- The `Check Links` badge in the README points at `actions/workflows/links.yml`; keep that path in sync if the workflow file is renamed.

To reproduce the check locally (same coverage as CI):

```bash
lychee --verbose --no-progress './**/*.md' './**/*.html'
```

## Git and PR conventions

- `master` is the live branch. `develop` is stale (last touched in 2022) — do not target it.
- Recent commits use Conventional Commit prefixes (`feat:`, `fix:`, `docs:`); older ones are plain ("Update README.md"). New commits should use the prefixed style.
- External contributions arrive as PRs from forks with branches like `patch-1` or `new-resources`; the maintainer merges them. Keep PRs to a single logical change.
- There is no `CONTRIBUTING.md`; the README and the awesome-list conventions are the only stated rules.
